# v1.0.32 隔離CLIテスト

1. 通常の起動経路から独立した、JSONシナリオを実行するCLI入口を設ける。
2. 設定検証、初期値、出力排他、音声経路、効果音の生成、オーバーレイの表示条件を既存処理と共有する。
3. 配布用バイナリと同じCLI入口で、状態遷移、失敗時の保持、通常常駐への非干渉を確認する。

## 実装

`--test-scenario` は通常起動より先に分岐する。シナリオと結果はJSONで、状態は試験プロセスのメモリーに保持する。再起動操作は適用済み設定をJSON経由で復元する。設定適用の検証に失敗したときは、実効出力と適用済み設定を維持する。

試験は製品と共通の初期値、設定・RVCパラメーター検証、音声経路生成、出力切替と押下中の排他、効果音波形、オーバーレイ表示条件を使う。通常常駐へのIPC、グローバルキー登録、設定ファイルへの書き込み、実デバイスへの接続は行わない。

## 検証結果

- Rustの通常回帰100件とWindows設定画面の回帰1件が通過した。
- デバッグ・リリースの両構成で試験シナリオ35操作が成功した。操作失敗時のロールバック、不正JSONと通常引数の拒否、終了コード0／1／2も確認した。
- リリース構成の試験中に導入済みv1.0.31が同じPIDとEXEで稼働し、利用者設定と試験入力のSHA-256が変化しないことを確認した。
- 隔離CLIの対象は状態遷移・音声経路・波形・表示条件。実音声の出力、RVC推論、Windowsの実キー操作と実画面表示はこの試験の対象外。

## 公開前の修正

v1.0.31でToysから初めて設定を開く際に応答が途切れた。設定画面では候補のID・名前・接続状態だけを取得し、デバイスごとの音声クライアント生成と対応形式の照会を省いた。音声診断用の列挙は従来どおり。管理試験ではToysと同じ2秒の期限で応答を検査し、初回表示の所要時間を記録する。

詳細計測では音声デバイスの列挙が約21ミリ秒、前面化が約37ミリ秒だった一方、主キー欄を含むキー設定ページの構築が数秒を占めた。主キーの候補は操作する行だけ読み込む。管理要求では基本設定を表示した時点で completed を返し、残りのタブの構築が終わるまで入力を無効にする。手動起動時も、表示要求を受けるまでは設定画面を作成・表示しない。

## 配布候補の確認

- 最終配布物のEXEで隔離CLIの35操作と異常系を再確認した。設定変更・適用・初期値への復元、出力切替と押下中ON、効果音、オーバーレイを含む。管理要求は初回と設定を閉じた後の再表示を各3回確認し、応答時間はそれぞれ234～357ミリ秒と262～509ミリ秒だった。
- 実画面では基本設定、主キー候補のF24までの選択、RVC無効時のタブ移動、効果音欄、MICと送信停止のオーバーレイを確認した。既定の再生デバイスでWASAPIの効果音送出が完了し、全出力OFFで実マイクの入力ワーカーがエラーなく稼働した。物理キー、実モデルを使うRVC推論、聞き取りによる評価は未確認。
- 設定画面とオーバーレイの録画は、同版の `logs/recording-0f6d737283024347a1a3a2c70c5400ab/` と `logs/recording-727b7d4c80634886b2d701cf2ecffc7f/` に保存した。

## 公開とToysでの確認

- `e2a44db` を [GitHubのv1.0.32プレリリース](https://github.com/KotorinChunChun/VoiceMixerMicRouter/releases/tag/v1.0.32) として公開した。[Toysの公開一覧更新](https://github.com/KotorinChunChun/KotorinToys/actions/runs/42466213505) は成功し、Toysの公開台帳からv1.0.32の製品識別、容量38,648,876バイト、SHA-256 `6e338a5d20c127df5dc244d07a523da36453e76e160899617f3e4836251ceb55` を照合した。
- Toysの取得処理で公開インストーラーの直接URLが再試行後もHTTP 504を返した。GitHub Releaseから `gh release download` で取得した同じファイルを公開台帳の容量とSHA-256で照合し、Toysの導入処理に渡した。v1.0.31からv1.0.32に更新でき、導入済みバイナリの一致と更新による利用者設定の変更がないことを確認した。Toysの通常経路による直接取得は未達。
- Toysの起動処理から導入済みv1.0.32が起動し、設定ウィンドウが開いた。初回の管理応答では空のJSONを読み込むエラーが再発した。同じプロセスに対する状態照会と設定の再表示は成功し、再表示の管理応答は16ミリ秒だった。公開ノートには直接取得と初回管理応答の事象を記載した。

## 公開後のローカル検証拡張

- 既存の `--test-scenario` に任意の仮想デバイス一覧と `route_probe` を追加した。[開発者ガイド](../../../docs/DEVELOPERS_GUIDE.md#仮想デバイスで入力切替と複数出力を確認する)の手順で、適用済み設定・押下状態を使った経路計画と、3出力の合成信号ピークをJSONで確認できる。
- 従来の隔離シナリオ35操作と異常系、仮想経路35操作（想定エラー5件）、Rust回帰100件が通過した。仮想経路はMIC、MIC-RVC、SPK-RVC、送信停止、同時押下と解放、既定先の循環と重複、未接続、既定先なしを確認した。稼働中の通常常駐のPID、利用者設定と試験入力のSHA-256は試験前後で一致した。
- この拡張は公開後のソース変更。実音声デバイス、実モデルによるRVC推論、聞き取りは今回の試験の対象外とした。
