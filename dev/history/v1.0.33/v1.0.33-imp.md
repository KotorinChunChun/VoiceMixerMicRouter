# v1.0.33 実装・検証

## 方針

GitHub mainを基準とし、未公開の撮影入口と隔離CLI拡張を統合する。公式flacenc 0.5.1を同梱し、heapless 0.9.4のエラー型に合わせて2か所を修正する。最小Rust版を1.88へ揃える。

## 工程

- [x] 依存更新と合成音声のFLAC検証、回帰テスト
- [x] 配布物ビルド、セキュリティ検査、管理連携とUIの確認
- [x] Push、リリース、公開配布物の照合と正式導入先の更新確認

## 実装と検証

- flacenc 0.5.1の公式配布からソースとライセンスを収録し、heaplessを0.9.4へ固定した。2か所のCapacityError対応に加え、録音末尾が32フレーム未満の場合の保存完了エラーを修正した。FrameBufの容量を最小32にして、filled_sizeに実サンプル数を保持する。短い最終フレームは[RFC 9639の4.1節](https://www.rfc-editor.org/rfc/rfc9639.html#section-4.1)に従う。
- 合成PCMの1・15・4096・8193フレームを、通常保存と録音ワーカーでそれぞれFLACへ保存・再読込みし、サンプル数と値、停止時の完了を確認した。
- Rust回帰101件、Python回帰22件が成功した。実機条件付きのRust試験10件は通常回帰の対象外。Python試験は専用Python 3.14環境とNumPy 2.5.5を使用した。
- リリース構成で隔離CLIの通常35操作と仮想経路35操作、異常系、利用者設定のハッシュ保持が通過した。heapless 0.9.4のOSV照合は該当0件。同梱ソースと公開予定差分のgitleaks検査は検出0件。
- v1.0.32に続いていたローカルCLI拡張と撮影用入口を統合した。既存のREADME・LICENSE作業は元の作業ツリーで保持し、公開mainを基準に別の作業ツリーで更新する。
- 配布候補の管理試験で、設定を閉じた後の再表示が2秒の期限を超えた。読み込み状態の画面を先に表示して管理応答を返し、選択欄の構築完了後に操作を有効にするよう修正した。修正後のRust通常回帰101件、設定画面の回帰1件、トレイとオーバーレイの回帰1件が成功した。
- 管理回帰では、固定250ミリ秒の待機を、設定画面が実際に閉じるまでの待機へ変更した。修正版で初回表示と再表示を各3回確認し、初回82～240ミリ秒、再表示210～451ミリ秒だった。3種類の起動経路の接続、PID検証、停止拒否、正常停止もすべて成功した。
