# v1.0.19 実装計画・作業記録

## 依頼

RVC変換中の入力切替では切替時点までに取り込んだ音を送出してから次の入力へ切り替える。入力4種類と出力3種類それぞれの切替音を設定可能にし、「なし」と複数の候補から選択直後に試聴する。初期値はすべて異なる音。既存の保存設定を保持する。

## 調査

現在のselect_graphは切替時にRVC出力を即座に閉じる。RVCにはPython処理中・共有リング・出力待ちが存在し、画面用の間欠実測値のみでは最後のフレームが送出されたことを保証できない。切替要求時に旧入力を遮断し、変換と出力の進捗を追跡したうえで新経路へ移る方式を検討する。RVCロード中は変換待ち音声がないため従来どおりMICや停止へ戻れること、切替の再要求、プラグイン障害、出力の切替を扱う必要がある。

- [x] 入力末尾の送信と切替状態の実装・回帰試験。
- [x] 操作別効果音の選択・試聴・保存・再生先と回帰試験。
- [x] 仕様・版番号・ビルド・実機検証、既存設定と稼働状態の保持。

効果音の既定再生先はWindowsの既定デバイスとし、任意の再生デバイスも選択できる。SPK-RVCの入力と効果音の出力が同じ場合、効果音前後だけスピーカー入力を無音化し、他の音もその間は入らないことをユーザーが承諾した。

## 実装・検証

RVC共有リングの入出力カーソルとプラグインが報告する遅延フレームを使い、入力側で取得済みのキューを含めた切替境界より後は無音を与える。旧出力の対応位置まで消化した後に最後の指定モードへ切り替える。音声スレッドを制御側のロックで止めず、要求を音声スレッドで消化する。ロード中・エラー中は待たず、30秒を超える障害時は送信停止とエラーにする。実処理が待機中は設定適用を一度拒否し、送信後に再適用できる。

7種類の短い操作音と「なし」を操作別に保存し、設定変更時は選択した再生デバイスで試聴する。Windowsの既定・既定の通信・個別デバイスを選択できる。RVCのSPK入力と再生先が同じ場合は、取得済みの旧入力を先に処理し、グラフの無音化反映を確認してから効果音を再生し、再生後に復帰する。選択デバイスの状態やOS環境によって音が鳴らない場合がある。

通常回帰：常駐88件、共通音声エンジン158件成功。共有リングで取り込み済みフレーム・変換後の出力位置・無音化を検証し、連続指定、RVCロード中の即時復帰、停止タイムアウトを確認した。実RVCモデルを使い全出力OFFで切替待ち完了を確認（約450ms）。既定再生デバイスの試験音再生、SPK-RVCで同じデバイスを使う間の入力無音・再生後の復帰を実機確認した。設定画面の追加タブと配置は試験用ウィンドウで確認した。

実RVC試験では相手側の受信音や発言末尾の音響を録音・測定していない。音声デバイス・RVC処理の異常による既存のキュー破棄は、この変更だけで回避できない。GitHubへのpush・Release公開は今回依頼されていないため行わない。
