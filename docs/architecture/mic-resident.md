# マイク常駐の内部構造

常駐1.0.17の構成。[現行仕様](../mic-resident-spec.md)が利用者向けの動作の正本で、本書は保守時の変更箇所と境界を示す。本体と共通の音声エンジンは[開発者ガイド](../DEVELOPERS_GUIDE.md)を参照する。

## 責務と変更箇所

入口は `src/src-tauri/src/bin/voicemixer-mic.rs`。以下は同階層の `mic_router/` 配下。

| モジュール | 責務 |
|---|---|
| `actions.rs` | IPC操作ID、キー保存順、既定キー、名称、設定画面の表示順 |
| `cli.rs` | 副作用のない引数解析と、単一起動・既存プロセスへの通知・初期化・診断 |
| `resident.rs` | 常駐の主ループ。画面操作、設定応答、音声ワーカー、状態保存の調停 |
| `config.rs`、`config/` | 設定型と検証、キー移行、保存、デバイス候補、音声グラフ生成 |
| `engine.rs` | 主ループに公開するコマンドと状態、および診断の入口 |
| `engine/routing.rs` | モードのグラフ選択、出力の重複整理、スピーカー入力の循環検査 |
| `engine/session.rs` | セッションとRVC準備・保持・解放、設定適用のトランザクション |
| `engine/worker.rs` | 音声スレッドの受信・進捗報告・再試行。sessionの子モジュール |
| `ui.rs`、`hotkeys.rs` | トレイ、ウィンドウ間通知、全アプリ共通の共存／上書きキー検出、押下・解放 |
| `ui/overlay.rs` | 表示ウィンドウと状態の所有、表示期限、クリック・ドラッグ・更新範囲 |
| `ui/drawing.rs`、`ui/icon.rs` | 二重バッファ描画とGDI資源、アイコン生成 |
| `settings_ui.rs`、`settings_ui/` | 設定窓の寿命、フォーム、Win32部品、RVC値の変換・検証 |
| `delay.rs`、`telemetry.rs` | 遅延計測、入力と出力のレベル履歴 |

## 境界を守る変更

- IPCの数値とJSON内のキー配列順は互換契約。設定画面の並び替えで保存順を変えない。新しい操作は `actions.rs` を起点に追加し、旧版移行は `config/hotkey.rs` で扱う。
- 画面から音声処理を直接実行しない。常駐ループからワーカーへ要求を送り、設定世代と応答を照合する。RVCの初回推論を含む準備は背景で進め、準備中のMIC復帰を妨げない。
- 用途名`output_labels`は表示専用とし、デバイスのfriendly nameや固定音声ノード名を置き換えない。後者は既存のルーティング識別にも使うため、表示名変更を音声再起動へ結び付けない。
- 設定保存、音声グラフの生成、実デバイスでのグラフ切替を分ける。共通BackendとPythonプラグインのプロトコルは常駐固有のUI変更に巻き込まない。
- オーバーレイは自身の状態を所有する。Win32の同期呼出しによる再入を考慮し、ウィンドウコールバックは共有参照を使い、ロックを保持したまま再入する操作をしない。窓を破棄してから状態を解放する。
- メーターの50ms更新で画面上のボタン領域を更新しない。二重バッファの完成画像から必要な矩形だけを転送する。同じ状態の定期通知では表示期限を延長しない。

## 検証から配備までの手順

この手順は、依頼された変更・検証・ローカル配備を再現するためのもの。文書整理だけの依頼ではリンクと根拠を確認し、アプリを止めたり試験音を流したりしない。新しい録音、OS既定先の変更、自動起動の新規登録、署名、外部公開は今回の依頼に含まれるかを別に判断する。過去の一度の実行を恒久的な許可へ転用しない。

### 1. 変更箇所と試験を対応させる

現行仕様・関連ソース・最新の完了記録を確認し、既存の利用者変更を保持する。古い未チェック行だけで完了済み工程を再開しない。動作契約は[現行仕様](../mic-resident-spec.md)、各回の事実は[実機検証結果](../../dev/testing/mic-resident-results.md)を参照する。

| 変更対象 | 選ぶ試験・根拠 |
|---|---|
| 保存、CLI、操作定義、経路の判断 | 常駐の通常回帰。旧設定の固定期待値、IPC番号、保存順を維持し、実装と同じ新定義だけから期待値を作らない |
| トレイ・オーバーレイ・設定画面 | 通常回帰に加えて下記GUI2件。配置、クリック、フォーカス、期限、部分更新まで確認 |
| 背景準備、モデル保持、設定適用 | 通常の状態遷移試験に加え、必要な実モデル試験と下記の背景準備シナリオ |
| SPK入力・デバイス解決 | `live_speaker_input_shares_rvc_and_stops_feedback`。設定適用・復元は `live_settings_keep_plugin_and_rollback_failed_device_and_model` |
| 遅延、短音抑制 | `virtual_device_delay_covers_queued_audio`、`plugins/rvc-cuda/tests/test_transient_gate.py`。実録音を評価する場合は利用者が明示した音声だけを別工程で扱う |
| OS既定デバイスへの追従 | `follows_live_windows_defaults_without_reloading_rvc`。OS設定を一時変更する試験なので、既定変更まで許可された検証でだけ実行 |
| 文書・スキルのみ | 相対リンク、参照する現行仕様、適用範囲、スキル形式を確認。音声試験を追加しない |

実機試験はignore付きで、条件は各試験の宣言を読む。必要な試験のみ個別実行し、`--ignored`だけで全部を実行しない。実デバイス試験の設定を指定する `VOICEMIXER_MIC_TEST_CONFIG` と、OS変更を有効にする `VOICEMIXER_MIC_TEST_CHANGE_DEFAULTS=1` を混同しない。ファイル分割後は旧モジュール名のフィルターで0件になる場合があるため、成功終了に加えて意図した試験名・実行件数を確認する。

### 2. ビルドと通常試験

以下を順に実行し、各終了コードを確認する。既存の開発差分を含む全体フォーマットを無条件に適用せず、変更ファイルを対象にする。共通BackendやPythonを変更した場合は、その変更を覆う試験も追加する。

```powershell
cd C:\develop\VoiceMixerMicRouter
cargo test --manifest-path src/src-tauri/Cargo.toml --bin voicemixer-mic
cargo check --manifest-path src/src-tauri/Cargo.toml --bin voicemixer-mic --all-features
cargo build --manifest-path src/src-tauri/Cargo.toml --release --bin voicemixer-mic
```

TEMP権限で試験が失敗する環境では、現在の試験プロセスの `TEMP`／`TMP` をリポジトリの `tmp/` へ一時的に向ける。元の値を保存し、終了後に戻す。ユーザー／システム環境変数は変更しない。環境由来の失敗と製品の不具合を分け、通常セッションで再試験した場合はその条件も記録する。

### 3. 実機試験と背景準備

開始前に対象EXEのパス・PIDと元のモード／設定を確認する。利用中の常駐を止める場合は音声が一時停止することを知らせ、GUIでキー・フォーカス・カーソルを操作する前にも案内する。通常終了を待ち、試験用プロセスと本番の常駐を同時に動かさない。設定・退避データは公開成果物やGitへ含めない。

```powershell
cd C:\develop\VoiceMixerMicRouter
pwsh -File .\dev\scripts\Start-MicRouter.ps1 -Mode Stop
# 対象プロセスの終了を確認してから、必要な試験を実行する。
cargo test --manifest-path src/src-tauri/Cargo.toml --bin voicemixer-mic native_commands_menu_icons_and_nonactivating_overlay -- --ignored --test-threads=1
cargo test --manifest-path src/src-tauri/Cargo.toml --bin voicemixer-mic settings_controls_roundtrip_and_page_layout -- --ignored --test-threads=1
```

実機試験は独立版の専用GUIと、対象の音声シナリオを選んで実施する。

背景準備を変更した場合は、次のシナリオも現行診断項目に合わせて確認する。過去の一時スクリプトや特定PIDに依存させない。

1. RVC未準備の状態からRVCを選び、`rvc_loading=true`を観測する。
2. 完了前にMICへ戻し、MICの`running`とRVCの読込継続を同時に確認する。準備完了後もMICを維持し、メーター更新とエラーの有無を確認する。
3. 60秒程度の待機でモデル起動回数が増えないことを確認する。キューを調べる場合は、そのプロセス・プラグインに対応するリングを特定し、時間と滞留量を記録する。
4. RVC再選択で同じインスタンスを再利用し、明示解放後の再準備も確認する。設定失敗・復元の変更を含む場合は、それを覆う回帰試験も確認する。
5. `finally`相当の後片付けで試験プロセスを通常終了し、元の設定・モード・稼働状態を復元する。終了待ちが続く場合は対象の親子関係と失敗範囲を記録し、同名のPython等を一括終了しない。

過去の56.3msというMIC復帰、準備27.9秒、キュー最大0.34秒はその環境・設定での観測値であり、全環境の合否しきい値ではない。MICへの状態復帰時間を音響遅延とも呼ばない。

### 4. 設定と自動起動を保持した配備

配備前に元のEXEと設定を退避し、通常終了を確認する。更新先は既存の配備先を使用する。既存Startupを変更せず配備する場合は次のコマンドを使う。

```powershell
cd C:\develop\VoiceMixerMicRouter
pwsh -File .\dev\scripts\Install-MicRouter.ps1 -SkipBuild -NoStartup -NoStart
pwsh -File .\dev\scripts\Start-MicRouter.ps1
```

`-SkipBuild`は今回のソースからReleaseビルドが成功した場合だけ使用する。インストールスクリプトは通常終了や退避を代行しない。初回導入の手順は[利用ガイド](../mic-resident.md#配備と自動起動)を参照する。Startupからの起動を確認する場合は既存リンクの対象・引数を照合して起動し、再登録はしない。

配備EXEとビルド成果物のハッシュ、版表示、対象パスの単一PID、`status.json`のPIDと新しい更新時刻・`running`、元のモードを照合する。古い状態ファイルだけで稼働中としない。設定移行のない変更は設定JSONの前後ハッシュ一致を確認する。移行が仕様に含まれる場合は、意図した項目だけの差分と独自割当・デバイス・RVC値の保持を確認し、全体のハッシュ一致を要求しない。

### 5. 記録と完了報告

通常試験、実機測定、ユーザー確認、今回未実施の範囲を分けて[実機検証結果](../../dev/testing/mic-resident-results.md)へ追記する。MSTSCの過去のユーザー確認を消さず、新しい自動測定に置き換えたとも書かない。Startupリンクからの起動は実ログイン試験ではなく、状態正常は聴感評価ではない。RVC明示解放の成功例だけで、過去の子プロセス残存条件の全面解消としない。

検証用プロセスは終了し、継続利用する配備版は依頼された状態に戻す。GUI操作終了を知らせ、変更点・検証範囲・制約とともに、起動中でも任意の作業フォルダーから実行できる起動コマンドを載せる。人へ追加試験を依頼する場合は[利用ガイドのデバッグ起動](../mic-resident.md#設定診断)を案内する。

```powershell
pwsh -File "C:\develop\VoiceMixerMicRouter\dev\scripts\Start-MicRouter.ps1"
```

## 押下中ONの境界

`Command::Hold([bool;3])`で一時出力を更新し、通常の`Configure`応答・保存設定と分離する。`ResidentSession`の`output_holds`に押下がある間は通常出力値を押下値で置換し、循環検査・出力の重複解決・開始停止へ同じ実効値を渡す。RVCの再ロードは行わない。UI側は設定適用待ちでも解放を処理し、設定表示中も押下を保持する。`status.json`の`push_to_talk`は一時状態、`outputs[].enabled`は実効値。

共存は割当済みの入力も`CallNextHookEx`へ渡し、上書きは一致した主キーのdown/repeat/upを非ゼロ戻り値で抑止する。OSの`RegisterHotKey`予約は使わない。主キー・修飾キー解放、割当変更時の解放、通常前景で取り逃したキーアップを検査する。MSTSC中は非同期キー状態に依存せずイベントで解放を判断する。

オーバーレイは「設定」「入力」「出力」の3行で左ラベルとボタンの左右端を揃え、設定は2等分、入力はRVC有効時4等分・無効時2等分、出力は3等分の幅にしています。

P2T押下中の出力ボタンは青い背景と`P2T`の文字で通常ONと区別する。非対象出力はOFF表示となる。3出力のP2Tを同時押しした場合は押している出力をすべてONとし、一部を離した場合も残る押下だけをONにする。すべて解放すると通常表示・通常設定へ復帰する。切替は非対象の停止を先に行い、対象をその後に開始する。P2Tで通常設定を保存・上書きしない。

設定タブの添字は基本0・キー1・RVC2。`applied()`は成功した設定をbaseへ反映してbusyを解除し、画面を破棄しない。無効キーの有効チェックだけを残し、行の設定値を消さずにEnableWindowで入力を無効化する。busy解除時も行ごとの有効状態を再計算する。

設定の反映元をEditor/Shortcutで区別する。Editor応答だけ`applied()`で編集基底とキーの表示を確定し、Shortcut応答は`sync_shortcut()`で対象項目だけ同期する。未適用の他項目と入力フォーカスは保持する。反映中のキーはFIFOへ保留し、MIC/送信停止・設定表示・終了・P2Tは処理を継続する。キー切替の反映中は適用のみ無効化し、ページや編集中の入力欄は無効化しない。設定表示だけではP2Tを解除しない。トレイ・オーバーレイのクリック排他は継続する。

## 入出力別メーターとRVC無効化

`rvc_enabled`はSettingsに独立保存し、既存設定にはtrueを補う。利用可能モードの正規化を常駐・ワーカー・セッション・グラフ作成で行う。無効化は読込中でも先にMICを選択し、既存の背景解放予約を使って準備完了結果を破棄する。RVC無効中の再試行・モード選択・ノイズ操作を入口でも遮断する。再有効化はロード要求と分離する。

入力は選択モードに対応するデバイスワーカーだけを実行する。停止時は双方を止める。共通Runtimeはruntime_enabled=falseのノードを音声処理・メーター計算の前で除外するため、新しい監視用取得を追加しない。Collectorは入力1つと出力3つを集約し、実稼働していない出力のイベントと履歴を除外する。代表値output_peakは診断互換用に残すが、表示にはoutput_peaksの各値を使う。遅延計測先の3→1→2優先は変更しない。

入力ワーカーの稼働確認は`diagnostics.inputs.microphone.active`と`speaker.active`を使う。v1.0.14の実機検証では停止後の`nodes[].state`に以前のrunningが残る例があったため、状態ラベルだけから取得継続と判断しない。activeはNodeRuntimeManagerの実リソースの存在を参照する。

メーター更新矩形は入力y52〜68・出力y94〜110・遅延y112〜126の3つ。GetUpdateRectが返す外接矩形にはボタンが含まれ得るが、実際の無効領域は3矩形の和集合で、二重バッファの転送もそのクリップ内となる。表示期限と全体再表示へ結び付けない。

## 共存／上書きと設定画面

Hotkey.handlingは既存設定でCoexistを補う。KeyStateは抑止した主キーを解放まで記録する。上書きkeydownはOSのGetAsyncKeyStateへ反映されないため、その主キーを非同期状態だけで解放扱いにしない。修飾キーの解放ではP2Tを解除し、主キーのkeyupは引き続き抑止して対を保つ。MSTSC前景時のフック再登録と、非同期キー状態を使わない判断を維持する。無効なRVC関連キーは有効割当から外す。

旧既定のShift移行はhotkey_defaults_revisionで一度だけ判定する。保存添字は維持し、表示順だけ変更する。列IDも旧Shift=1/Ctrl=2/Windows=3/Alt=4/主キー=5を保ち、ネイティブ部品の作成順をCtrl→Shift→Alt→Windows→主キーへ揃える。共存/上書きは列6。設定画面の幅は960px、文字16pxを維持する。公開GitHubリンクは標準Buttonのowner-drawを使い、下線・指カーソル・フォーカス枠を表示する。RVC各項目と短音抑制は標準Tooltipを使い、文字列とサブクラスの寿命を設定窓に合わせる。comctl32 v6の有効化に依存しないようTTTOOLINFOWはV2サイズで登録する。モデルのフォルダー解決はplugin基準の相対パスと絶対パスを区別し、未保存入力を使う。
